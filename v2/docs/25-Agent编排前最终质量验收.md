# Agent编排前最终质量验收

2026年10月20日，pre_agent_v1。本阶段完成Agent编排前的本地推荐、证据、受控生成质量收尾：语义审阅、可复现错例修复、真实DeepSeek小批量对照和运行交付。多轮状态、工具选择与Agent循环尚未实现。

## 标注来源与覆盖

两项独立代理审阅任务分别逐条阅读类别/约束与软偏好场景；没有把自动cue直接当立场标签。基线140家次餐厅、196条证据均已代理标注；修复后140家次餐厅、188条证据均已代理标注，涵盖28条有结果查询。12条澄清/无结果仍按功能契约审计。

这些标签是**agent-reviewed silver（代理审阅的银标），不是独立人工金标**。两项任务按场景分工，并非同一批样本的双人盲标；没有一致性系数。语义判断可能错误，不能称为人工准确率或实际用户满意度。原始待人工复核表继续保留空值；银标、判断依据和来源另存，不冒充原表的人工复核。

所有标注通过只读字段、快照、合法值、去重与标注者检查。迁移到最终代码快照时，仅对查询、商户、名次、类别、摘录、来源编号等只读内容完全一致的记录转移原判断；新返回的软偏好记录另行逐条审阅。原始Yelp文本及逐条标注都留在Git忽略目录。

## 错例根因与修复

“约会/浪漫”主题含有`date night`，原BM25拆词后，仅含普通`night`的评论也能入选，出现把夜间拥挤、菜品和酒品评论当约会相关证据的情况。

已先添加失败测试，再修复：软偏好摘录必须命中完整主题词或短语，不能只有短语里的普通词；补充`for a date`、`on a date`、`date spot`等明确表达。包含否定的真正相关评论仍可被召回，不能为了提高正向比例删除它们。测试同时覆盖拆句后词语分处两句、正常约会表达、商户归属和重复评论ID。

没有按餐厅ID设特例，也没有训练新模型或重新选择历史排序参数。主题词展开会影响查询召回，因此q14/q19返回池发生变化：过滤掉部分无关夜间评论，新增两家带直接约会描述的餐厅；其余8条软偏好查询的摘录未变。不能把两个不同返回池的NDCG当成固定全目录金标上的排序增益。

Precision相关阈值为餐厅relevance≥2，按实际返回的前5家计算；NDCG的理想排序只限当前返回池。该40条查询参与发现和修复问题，属于迭代开发集，绝非盲测。证据不足增多是过滤弱匹配后的真实结果，不把它包装成全面提高覆盖率。

已知保留的弱点包括：文化聊天、服务员未打断谈话，不足以证明适合聊天；户外吧台不等同于户外座位；“faux outdoor garden”的实际户外性质不清楚；评论者的泰裔身份不能证明餐厅供应泰餐。类别事实可以支持类别匹配，但不让无关评论替代证据。多语言措辞可能改变返回顺序，未宣称跨语言完全一致。

## 真实DeepSeek对照

使用本机既有配置，显式运行一次最多5条的真实对照，选择q11–q15：安静咖啡、聊天咖啡、户外座位、约会意大利菜、安静中餐。每条只请求一次，无自动重试；未运行第二轮付费探测。查询和评论来自固定历史数据，没有传入历史用户画像或专用user_id。

| 项目 | 实测 |

| 模型 | deepseek-flash |
| 服务商尝试 / 计划校验成功 | 5 / 5 |

耗时涵盖上下文构建、生成请求与解析，是5个样本的顺序小批量结果，不能当生产P95或完整推荐接口延迟。tokens来自服务商usage，未换算账单金额。

q13模型少选了一条支持性引用，其余非支持引用未减少；q15两种方式都没有环境证据，只能说明结构化事实并明确证据不足。该批结果**没有证明DeepSeek选择优于模板**。继续保留严格白名单、受控渲染、可选生成和模板降级；不开放自由发挥，也不因接入大模型就宣称推荐更准确。
