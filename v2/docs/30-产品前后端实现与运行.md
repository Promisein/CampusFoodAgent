# 产品前后端实现与运行

日期：2026 年 10 月 21 日。API 版本 0.8.0。此阶段把现有推荐系统和多轮 Agent 接入同源 Web 产品入口，不替换召回、排序或 RAG 模型。产品入口是 `http://127.0.0.1:8100/app`。

## 已实现

- 注册、登录、退出：独立随机账户 ID，密码 PBKDF2 盐化散列，登录失败限速；7 天 HttpOnly 会话 Cookie，写请求还要 CSRF 令牌。同源页面不把令牌写入 localStorage。
- 账户拥有的多轮对话：可创建、恢复、继续和查看近期对话。服务器从 Cookie 得出用户 ID，不采用页面提供的 Yelp 用户 ID。跨账户读取和写入返回 404。
- 发现页：设置 Tampa 中心点、半径和价格档；输入自然语言，查看推荐、条件、评论摘录、解释；收藏商户并在收藏页查看。桌面和手机宽度均可用。页面以文本节点显示外部内容。
- `CAMPUSFOOD_MODE=product` 会关闭原先匿名的 `/agent`、`/demo`、Agent/反馈/用户历史 API 与公开推荐 POST，根路径转到 `/app`。`local` 模式仍保留开发演示。
- 请求失败时给出页面提示；对结果不确定的会话写请求，前端保留相同 `turn_id`、版本和内容供重试。后台使用原有幂等机制，避免重复收藏。

## 本机运行

在 `v2/backend` 目录，用已有虚拟环境执行：

```powershell
$env:CAMPUSFOOD_MODE = 'product'
$env:CAMPUSFOOD_COOKIE_SECURE = 'false'
.\.venv\Scripts\python.exe -B -m uvicorn app.main:app --host 127.0.0.1 --port 8100
```

然后访问 `http://127.0.0.1:8100/app`，注册至少 12 位密码的账号。上述 `COOKIE_SECURE=false` 只适合本机 HTTP；经 HTTPS 反向代理提供服务时保持默认的 Secure Cookie。若已有 8100 服务，先停止旧进程，避免仍在展示上一个版本。数据必须已按此前文档处理到 `data/processed`，可用的召回/排序模型在 `data/derived`。如果模型产物缺失，既有推荐层会按其回退机制运行；页面不会自动训练。

页面默认勾选“用 DeepSeek 理解表达”，每次可能消耗 API 额度；不想调用时取消勾选。密钥只填在 `v2/backend/.env` 的 `DEEPSEEK_API_KEY`，不要粘到页面、代码或 Git。无密钥时仍可试用规则理解和基础推荐；复杂表达的覆盖率会降低。RAG 的模型引文选择是单独的可选勾选项。

## Docker 本机预览

在 `v2/backend` 目录，先保证 `data/processed` 和 `data/derived` 已有实际数据；若还没有 `.env`，把 `.env.example` 复制为 `.env`，按需填密钥，然后执行：

```powershell
docker compose -f compose.product.yml up --build -d
docker compose -f compose.product.yml ps
```

Compose 只绑定本机 `127.0.0.1:8100`，持久化账户、Agent 会话和收藏所在的 `data/derived`，只读挂载处理后的 Yelp 数据。每次只启动一个 Uvicorn worker，避免多进程本地 SQLite 管理问题。此配置用于本机预览，不是公开互联网部署方案。

## 数据、身份与上线边界

新注册账号与 Yelp 离线用户并不相同，没有原始 Yelp 历史画像。现阶段新账号的个性化主要依赖当前请求、会话条件和已有模型的冷启动回退；收藏和行为会持久化，但不会实时重训召回或排序。显示的商户和评论是 Yelp 历史数据，不能保证今日营业、预约、价格、过敏安全或对话描述中的主观场景完全准确。当前城市只支持 Tampa。

这是单机产品试运行。公开上线前还需 HTTPS 反向代理、入口限流、数据库备份与恢复演练、监控、密码重置/邮箱验证，以及用户对话质量和数据许可的独立验收。不要在公网直接暴露本机 Compose 配置。产品模式只关闭已知旧演示路由；生产部署还应由反向代理明确允许的公开路径。
