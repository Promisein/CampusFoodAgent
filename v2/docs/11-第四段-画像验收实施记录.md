## 3. 画像仓库

内部接口：

```python
class UserProfileRepository:
    def load_manifest(self) -> dict: ...
    def load_profiles(self) -> list[dict]: ...
    def get_profile(self, user_id: str, target_split: str) -> dict | None: ...
```

仓库行为：

- 校验 `profile_manifest.json` 必需字段；
- 按 manifest 中的文件名加载画像；
- 校验每条画像的 23 个必需字段；
- 重复 `(user_id, target_split)` 时快速失败；
- 缺文件时报告完整路径；
- manifest、画像列表和查询索引在进程内缓存；
- 未知用户返回 `None`。

仓库是内部 Python 数据层，没有把 Yelp 用户标识暴露成公开 HTTP 路由。

## 4. 真实数据集成验收

集成测试不依赖本机已有 `data/derived`，而是在 pytest 临时目录中执行：

```text
processed interactions
-> split_interactions
-> 临时 Train/Validation/Test/Cold-Sparse
-> build_profile_snapshots
-> 临时 6,046 条画像
-> UserProfileRepository
-> 可追溯性与防泄漏断言
```

验证内容：

1. 切分数量为 30,978 / 3,023 / 3,023 / 62,976；
2. 画像总数为 6,046；
3. 唯一 `profile_id` 数量为 6,046；
4. warm 用户数量为 3,023；
5. Validation 历史数等于 Train 历史数；
6. Test 历史数等于 Train 历史数加 1；
7. `cutoff_interaction_id` 与对应目标一致；
8. 目标 ID 不进入最近历史；
9. 最近商家全部存在于 processed Business；
10. 历史末端排序键小于目标排序键；
11. 测试前后 processed 文件大小和修改时间不变；
12. 在线推荐仍返回 `processed_geo_keyword_evidence`。
