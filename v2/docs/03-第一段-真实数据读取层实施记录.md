## 1. 本段目标

建立独立的 processed 数据访问模块，读取并校验：

- `data_manifest.json`；
- `businesses.jsonl`；
- `representative_reviews.jsonl`。

本段不修改 API、请求模型或推荐逻辑，在线推荐仍保持原 fixture 行为。

## 3. 实现接口

```python
class ProcessedDatasetRepository:
    def __init__(self, data_dir: Path): ...
    def load_manifest(self) -> dict: ...
    def load_businesses(self) -> list[dict]: ...
    def load_representative_reviews_by_business(self) -> dict[str, list[dict]]: ...
```

职责：

- 从调用方指定的数据目录读取文件；
- 检查必需文件是否存在；
- 校验 manifest、Business 和 RepresentativeReview 的必需字段；
- 在错误中返回文件、行号和缺失字段；
- 把代表评论按 `business_id` 分组；
- 在同一个仓库实例内缓存三类读取结果。

## 4. 字段校验

### manifest

当前服务依赖以下顶层字段：

```text
data_version
selected_city
kept
```

### Business

校验 processed Business 的 15 个字段，包括：

```text
business_id, name, categories_raw, categories_normalized,
latitude, longitude, city, state, stars, review_count,
price_level, hours, attributes, is_open, data_version
```

`price_level` 和 `hours` 的值可以为 `null` 或空对象，但字段必须存在。

### RepresentativeReview

校验 8 个字段：

```text
review_id, business_id, user_id, rating,
review_date, useful, text, source
```

## 5. TDD 过程

本段按 RED → GREEN 循环实现：

| 轮次 | RED 失败原因 | GREEN 最小实现 |
| --- | --- | --- |
| 1 | `app.data_repository` 不存在 | 实现三类读取和评论分组 |
| 2 | 缺失文件错误不符合可读契约 | 增加统一 `_require_file()` |
| 3 | 缺少 `business_id` 的 Business 未被拒绝 | 增加 Business 字段校验 |
| 4 | 缺少 `review_id` 的评论未被拒绝 | 增加评论字段校验 |
| 5 | manifest 缺少 `selected_city` 未被拒绝 | 增加 manifest 字段校验 |
| 6 | 重复调用重新读取文件 | 增加实例级缓存 |

每个测试都先观察到预期失败，再写最小实现并确认通过。
