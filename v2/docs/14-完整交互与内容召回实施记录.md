# 完整交互与内容召回实施记录

日期：2026年10月20日。数据版本：`tampa_full_reviews_v1`；实验版本：`fullcity_content_v1`。

## 目标与范围

针对上一阶段历史截断、Cold用户占比高、候选不可见等问题，保留同一Tampa商户集合的全部Review交互，建立同目标旧/新历史对照，并增加基于类别TF-IDF与价格偏好的内容召回。保留旧processed、旧派生画像、baseline_recall_v1和原报告。在线API仍为规则引擎。

`backend/app/data_pipeline/full_city_corpus.py`以旧商户文件为固定商户宇宙，流式扫描原始Review，不设总量或单商户上限。只保存interaction_id/user_id/business_id/rating/event_time/event_type/source，不复制评论正文。选中评论的ID、评分、时间和用户字段异常即失败，不把无效记录静默当负样本。

扫描全部6,990,280条原始评论，排除其他商户6,657,451条。新数据时间范围2005-08-18 18:55:21至2022-01-19 19:45:43。商户文件与旧版字节相同，SHA256也相同。

新目录：`backend/data/derived/tampa_full_reviews_v1`。构建在临时目录完成，输入验证成功后发布；拒绝覆盖包含源文件的目录及无本数据版本标记的非空目录。manifest记录源Review的5GB文件SHA256、商户SHA256、构建代码SHA256及选择规则。新交互没有文本字段，不直接替代当前在线repository的输入。

发布由`backend/app/artifact_io.py`统一处理：暂存目录写完后计算全部文件SHA256和大小并校验，再以同父目录重命名切换完整版本。旧版本保留在`.目标目录.previous-唯一标识`中；普通发布失败回滚，进程中断最多使目标目录短暂缺失，旧完整版本仍可恢复，不暴露混合版本。研究入口验证完整数据manifest；代码指纹包括资格判断、校验器及发布辅助模块。

## 共同目标对照协议

固定沿用上一阶段的两个截止点，不重新按完整数据分位划分：

- validation：2017-11-08 20:34:02。
- test：2019-05-30 23:02:52。

完整数据中每用户每窗口首次4—5星、截止点未访问商户是共同目标。legacy_history与full_history使用完全相同的目标与时间窗口；主表all分母相同。分群也固定为完整历史截止点0/1—4/至少5条的Cold/Light/Warm，保证分群比较仍是同一用户集合。

各模型自己的实际历史分群另存`model_history_cohorts`：旧样本可能遗漏一个用户已有的真实历史，使其在旧模型中变Cold。完整历史可见商户集合也可能更大；此对照衡量采样对历史信号和候选资格的整体影响，不能将所有差异单独归因于某一因素。

模型只能读取其输入中的`event_time < cutoff`交互；同时间戳不进入历史。目标评论及未来文本、评分、位置不提供给召回器；完整未来只用于固定标签。旧交互必须是完整交互的一致子集，同ID字段冲突即失败。

## 内容模型

`backend/app/retrieval/content.py`新增ContentIndex，复用原BaselineIndex，原有三种召回默认行为不改。

1. 商户类别转小写、去重，去掉泛标签Restaurants和Food。
2. 在指定候选商户集合统计IDF：`log((1+商户数)/(1+类别商户数))+1`，商户向量单位归一化。
3. 用户向量由历史最新评分>=4的商户向量按`rating-3`加权，再归一化。
4. 内容分为余弦相似度；用户历史平均价格和候选价格均已知时乘`1/(1+价格差)`。
5. 返回匹配类别和历史种子商户，便于解释；Cold用户纯内容通道为空，合并通过热门兜底。

这是一套类别内容基线，不是语义Embedding或文本RAG。类别、价格、坐标是下载静态快照，不能保证完全恢复历史属性变动。

## 可见性与比较方法

| 变体 | 历史输入 | 候选资格 | 场景 |
|---|---|---|---|
| legacy_history | 原10万交互中截止点之前部分 | 本输入截止点前有评论的商户 | 全城、模拟10km |
| full_history | 完整交互中截止点之前部分 | 完整输入截止点前有评论的商户 | 全城、模拟10km |
| full_snapshot_catalog | 完整历史 | 假设全部下载商户资料截止点前已知 | 仅全城，条件实验 |

snapshot_catalog允许内容通道发现无交互商户，但这是明确的资料可见性假设，不得把该结果称为严格历史无泄漏效果。ItemCF仍无这些商户的共现，热门统计不读取未来评分。

每变体比较热门、ItemCF、内容、旧双路交替合并、新三路CF/内容/热门交替合并，预算100。无RRF、无LightGBM，不按test改参数。

## 流式评估与产物

`backend/app/evaluation/content_study.py`使用指标累加器，只保留计数、覆盖集合、逐请求排名顺序摘要及每原因少量trace。全部请求都做候选合法性、去重、已见排除检查；样本trace不是全量请求日志。

`backend/data/derived/fullcity_content_v1`输出：

- metrics.json：总体/共同分群指标、资格覆盖、实际历史分群、内容互补和预算损失、候选摘要。
- study_manifest.json：四个输入文件SHA256、代码SHA256、Python环境与配置。
- content_models.json：各变体截止点的IDF与商户向量，不包含未来评论。
- target_queries.jsonl：完整共同目标，本地保留用户标识，不提交。
- trace_samples.jsonl：匿名用户、目标、候选与前三条解释，仅分原因样本，不提交。
- report.md：自动生成的完整结果。

聚合指标副本和可读结论位于[实验报告](15-完整交互与内容召回实验报告.md)及`docs/experiments/fullcity_content_v1/`。完整原始数据、交互、模型和trace继续被git忽略。

## 复现

在`v2/backend`目录：

```powershell
$env:PYTHONNOUSERSITE = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
$foodPython = 'D:\anaconda3\envs\chedian-eat-agent\python.exe'
& $foodPython -B -m app.data_pipeline.full_city_corpus
& $foodPython -B -m app.evaluation.content_study
& $foodPython -B -m pytest tests/ -q -o addopts= -p no:cacheprovider
& $foodPython -B -m pip check
```

再次运行数据构建会完整扫描原始5GB文件；仅复现实验可直接运行第二条命令。全部使用CPU和Python标准库，无新增pip依赖。
