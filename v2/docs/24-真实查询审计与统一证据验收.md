# 固定查询审计与统一证据验收

2026年10月20日，query_quality_v1。本阶段完成固定查询、共享证据检索、演示页引用对应、真实Tampa目录功能审计及人工复核导入工具。40条查询由开发代理编写，覆盖真实使用场景，但不是实际用户日志、人工相关性金标或盲测集。

后续已完成代理银标审阅、错例修复和5条真实DeepSeek对照，最新结果见[25最终质量验收](25-Agent编排前最终质量验收.md)。本报告保留query_quality_v1原始基线数字，人工金标仍未提供。

## 本阶段改动

原商户卡片采用词汇命中数选评论，上方RAG采用BM25选句，导致同一商户的两处证据不同。本阶段把商户内BM25句子检索统一到`app/evidence.py`，卡片与RAG使用同一算法、主题展开、商户白名单和去重规则。

卡片新增`cue`、`citation_id`、`used_in_answer`。例如`b1_c2`与上方说明中的同编号对应；模型只选其中一条时，另一条标为“相关证据，本次说明未引用”。未覆盖的后续商户不分配回答编号，并明确显示未被本次说明覆盖。关闭说明时仍可查看相关证据。引用编号仅在当前响应内有效。

本次未调整召回候选、RRF权重、学习排序或历史实验参数；证据文本、提示状态与引用标记有所变化。`generate_answer`开关不会改变商户顺序与分数。BM25只衡量词项相关性，negative_cue等规则不承担支持/否定的最终语义判定。

独立审查发现重复review_id时，旧的全文回填方式可能引用另一条重复记录的全文；已增加先失败后通过的回归测试，保证所选摘录、来源和全文来自同一条记录。RAG上下文仍只接收摘录，不因该修复加入整篇评论。

## 固定40条查询

固定输入位于`backend/data/fixtures/query_quality_v1.json`：类别10条，软偏好10条，约束8条，澄清8条，无结果4条。覆盖咖啡、披萨、中餐、寿司、墨西哥菜、泰餐、意大利菜、汉堡、海鲜、纯素，以及安静、聊天、约会、户外、类别排除、半径与价格等级、金额/营业时间/过敏等不可验证条件。

功能期望直接编写在输入文件中，审计用原始商户类别、坐标、城市、数据集营业标记和价格检查；不是把解析器自己的输出当正确答案。该40条批量运行使用匿名请求；已知用户/冷用户和模型降级继续由既有自动化测试覆盖。本次没有新增真实个性化查询质量结论。

## 人工复核方法

先复制待复核表，保留原始表与清单：

```powershell
Copy-Item -LiteralPath data/derived/query_quality_v1/review_sheet.csv -Destination data/derived/query_quality_v1/review_sheet.completed.csv
```

仅填写`relevance`、`stance`、`reviewer`、`note`四列。其他列是绑定快照的只读内容；用UTF-8 CSV保存。完整复核表不应添加到Git。摘录可能缺少上下文，必要时查看同目录`query_results.json`内对应商户的全文；没有依据时留空或标为unclear，不代替现场验证。

| 行类型 | 标注列 | 可填值与含义 |
| --- | --- | --- |
| restaurant | relevance | 0=不相关或违反明确条件；1=仅部分相关/主要偏好缺证据；2=主要需求相关且有依据；3=高度相关且有充分依据 |
| evidence | stance | support=支持所问条件；contradict=否定所问条件；mention_only=提及但不能支持结论；irrelevant=无关；unclear=信息不足或冲突无法判定 |
| 两类 | reviewer | 标注者名称或代号，已标注行必须填写 |
| 两类 | note | 判断依据；多个偏好时写明对应哪一项 |

例如查询“安静咖啡店”，`not quiet`应标contradict；`great coffee`可与咖啡相关，但不能支持安静，应针对环境需求标mention_only并备注。自动cue可能由其他语境中的not触发，不能直接抄成contradict。评级针对历史证据，不证明今天的环境或安全条件。

导入与评分：

```powershell
.\.venv\Scripts\python.exe -B -m app.evaluation.query_quality --labels data/derived/query_quality_v1/review_sheet.completed.csv
```

导入拒绝未知/重复记录、过期snapshot_id、被改动的查询/商户/引用、非法标签及缺少标注者的已标注行。允许只复核部分行并报告覆盖率；未标注项不会自动当作负例。只有返回餐厅全部被标注的查询进入Precision与NDCG计算，相关阈值为relevance≥2。Precision分母为实际返回的前5家；NDCG理想顺序仅限当前返回池，不能代表全目录召回率或不同召回系统的全局比较。导入的标注者身份未经认证，工具不会自动把其称为独立人工金标。

## 验收边界

本阶段工程实现、功能审计和复核流程已完成，人工语义复核仍待实际标注者填写。因此当前可以确认两处引用一致、来源可追溯、条件处理符合这40个固定场景；还不能确认真实相关性、证据支持准确率、跨语言一致性或线上业务收益。回答依然使用受控中文模板，多轮Agent和自由语言改写不在本阶段范围内。
