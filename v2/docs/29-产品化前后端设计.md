# 产品化前后端设计

日期：2026年10月21日。本阶段交付同源 Web 应用 `/app` 与账户保护的 `/api/v2/product/*`。范围是单机试运行，不对公众互联网开放，也不声称已经具备商业生产环境的安全、可用性或人工质量验收。

## 使用流程

用户注册或登录后，在 Tampa 数据范围内设置位置、半径与最高价格档，输入自然语言需求。后端创建归属该账户的 Agent 会话，沿用已有自然语言理解、推荐、证据与收藏工具。页面显示当前有效条件、餐厅卡片、历史对话和收藏；可以继续说“便宜一点”“解释第二家”或明确收藏。会话重试继续使用现有 turn_id、版本与幂等机制。历史 Yelp 商户数据不能确认实时营业、过敏安全或实际可订座。

产品账户使用独立的随机 ID，绝不让浏览器选择 `user_id`。这些新账户没有 Yelp 历史画像，初期推荐按冷启动/查询逻辑运行；收藏持久化，不能宣称会立即重新训练排序模型。

## 架构与边界

- 继续使用同一个 FastAPI 进程、同源静态 HTML/CSS/JS、现有 AgentService 和推荐/RAG/反馈仓库。不复制推荐规则。产品 API 只做身份、归属、输入验证、错误映射和产品所需的响应裁剪。
- 新建 SQLite 账户仓库：用户名唯一，PBKDF2 盐化密码散列，随机会话令牌只存 SHA256，7 天有效期；登录失败限速。认证令牌放 HttpOnly、SameSite=Lax Cookie；修改请求还需要从同源认证接口获取的 CSRF token。产品模式应在 HTTPS 代理后启用 Secure Cookie。
- 新建产品会话归属表。读取、继续对话和收藏/历史始终从 Cookie 的账户 ID 推导，不接受客户端提供的用户 ID。新会话与归属分库存储，可能留下不对外可见的孤儿会话，但不能形成越权访问。
- `CAMPUSFOOD_MODE=product` 下关闭 `/demo`、`/agent`、旧版无认证 Agent/事件/用户历史接口及公开推荐 POST；`/app` 和产品 API 可用。默认 local 模式保留既有演示与自动化测试。
- 产品前端只用 `textContent`/DOM 节点渲染 Yelp 和模型文本；不注入 HTML。输入过程中禁用重复提交，网络不确定时保留 turn_id 并提供同请求重试。移动端与键盘可用。

## 验收

测试至少覆盖注册/登录/退出、Cookie 与 CSRF、错误密码与限速、跨账户会话隔离、账户派生的收藏与历史、旧接口在产品模式被关闭、真实推荐链路的产品 API 路径、页面刷新与移动宽度显示。保留现有离线回归与评价产物。上线前还需 HTTPS、反向代理限流、备份、监控、凭证管理、密码重置/邮箱验证以及独立人工对话质量验收。
