# 多轮Agent实现与最终验收

2026年10月21日，API0.6.0、agent_v1。推荐、受控RAG、多轮状态、工具编排、收藏与历史已形成可运行的本地演示闭环。生产认证、真实流量A/B和开放式自然语言泛化不在本次完成声明中。

## 直接运行

在`C:\Users\Jianing\Desktop\CampusFoodAgent\v2\backend`运行：

```powershell
.\.venv\Scripts\python.exe -B -m uvicorn app.main:app --host 127.0.0.1 --port 8100
```

打开`http://127.0.0.1:8100/agent`，填写可选演示用户ID后开始会话，依次发送：

1. 找附近的咖啡店
2. 再便宜一点
3. 最好有户外座位
4. 解释第二家
5. 收藏它
6. 查看历史

用户ID留空可以搜索、解释和收藏，但跨会话查看收藏/历史需要新建会话时填写演示ID。用户ID不是登录凭证。原单次推荐页仍在`/demo`，提供评分、不喜欢等完整反馈入口。

默认不调用模型。勾选“DeepSeek结构化动作规划”时启用模型动作提议；勾选“解释餐厅时用DeepSeek选择引用”时，仅在解释动作中启用生成。密钥仍在`backend/.env`，不会进入网页、会话或日志。两个选项同时开启且请求解释时，唯一模型预算留给引用生成，规划走规则。

## 状态与支持语法

会话包含固定初始城市、坐标、演示身份，以及可更新的类别、排除类别、软偏好、半径、最高价格等级和当前有序结果。

| 请求 | 行为 |
| --- | --- |
| 咖啡，不要披萨 | 搜索咖啡并保留类别排除 |
| 再便宜一点 | 价格等级上限减1，最低1；不承诺实际金额更低 |
| 近一点 | 半径减半，极小半径不扩大 |
| 最好有户外座位 | 保留原条件并追加软偏好；评论不保证真实满足 |
| 换成中餐 | 替换包含类别，保留排除、价格、半径及软偏好 |
| 取消户外要求 | 一次取消一个明确软偏好，包括对应英文残留词 |
| 取消排除披萨 | 取消一个明确类别排除 |
| 价格等级2 / 2公里内 | 明确设置当前上限；允许用户明确修改，不允许模型改槽位 |
| 解释第二家 / 收藏第二家 | 指向当前有序结果；不接受外部商户ID |
| 收藏它 | 指向刚解释/收藏的当前商户；没有明确焦点且多家候选时先澄清 |
| 查看收藏 / 查看历史 | 调用本地反馈仓库，只读当前演示身份 |

普通类别追加采用包含类别的“任一匹配”，明确“换成/改成”才替换。需要更换位置或演示身份时新建会话；旧会话保留至过期，不等于后台立即删除。新搜索成功后清除旧焦点；无结果不能继续引用旧列表。金额、现在营业、过敏保证、类别冲突和不支持的复合取消先澄清。澄清或搜索失败后，旧引用被阻止，直到有效搜索恢复。

自然语言仅支持既有有限中英文语法，不宣称任意对话理解。模型不自由生成事实，也不能将未知需求默认为已满足。

## 编排与工具

主流程为“动作分类 → 槽位合并/校验 → 受限工具执行 → 受控回复 → 持久化”。默认规则规划；可选DeepSeek只提出严格JSON动作和1–5的序号，Pydantic拒绝额外字段。最终动作须与代码识别出的用户意图一致，或保守转入澄清；模型不能发明槽位、任意工具名、SQL或商户ID。

| 工具轨迹名称 | 职责与边界 |
| --- | --- |
| plan_action | 可选模型分类，输入当前消息与允许动作，不发送用户历史画像 |
| search_restaurants | 复用既有个性化/匿名推荐、硬过滤、召回排序与曝光记录 |
| retrieve_evidence | 读取评论快照，供所选当前商户的证据检索 |
| explain_restaurant | 只解释当前商户，复用RAG白名单、引用校验和受控渲染 |
| save_favorite | 必须有明确收藏指令、当前商户及匹配曝光；稳定事件ID去重 |
| get_history / get_favorites | 只读当前演示用户的本地反馈 |

这是受限状态图和工具编排，不是无限模型循环。自然语言中的否定收藏、询问如何收藏、评论里的指令以及模型虚构的写操作都不能代替用户授权。

## 接口与持久化

```text
POST /api/v2/agent/sessions
GET  /api/v2/agent/sessions/{session_id}
POST /api/v2/agent/sessions/{session_id}/turns
```

创建请求包含latitude、longitude，可选city、radius_km、max_price_level、top_k（最多5）和user_id。轮次请求示例：

```json
{
  "turn_id": "由客户端生成并在重试时复用的唯一编号",
  "expected_version": 0,
  "message": "找咖啡",
  "use_model": false,
  "generate_answer": false
}
```

返回当前版本、生效条件、餐厅、说明、焦点商户、规划模式、工具轨迹和预算。GET还可恢复最近消息。未知会话404、过期410、版本或重复ID载荷冲突409、数据库忙/不可用503；参数越界422。相同turn_id及完全相同载荷返回原响应，保留原轨迹，不再次调用模型或收藏工具。

SQLite位于`backend/data/derived/agent_v1/sessions.sqlite3`，最多1000个未过期会话，每会话24小时、最多30轮，保留最近20条消息。会话存储最多250,000字符，餐厅证据仅存摘录，不拷贝整篇评论。状态变化与响应缓存同一事务提交，并发旧版本不能覆盖新状态。

本地单worker用SQLite事务串行化整轮操作，模型调用期间也持有事务；繁忙时其他写入可能返回503，适合演示，不宣称多worker吞吐。会话库和反馈库不是同一个事务；收藏使用稳定事件ID支持重试去重，不宣称跨库原子事务。会话ID是本地能力标识，无生产认证；不要把会话链接当公开分享入口。

## 执行限制

- 每轮最多4个工具步骤、1次模型调用；规划最多512输出tokens，说明最多1800，仍受.env中更小配置约束。
- 单次模型超时不超过6秒且不超过剩余轮次预算；没有自动重试。
- 每轮10秒为协作式截止时间，CPU或数据库工具不能安全中断；完成后的写入不会被谎称取消。预算在后续工具前检查，轨迹标记已完成工具的超时情况，不承诺硬实时SLA。
- 缺密钥、模型输出非法或服务商错误时规划回规则；说明按已有RAG机制退回模板。无法验证的条件保持澄清，不能借降级放宽过滤。
- 页面用textContent渲染不可信文本；模型选项默认关闭。网络失败保留原turn_id重试，409时同步版本并要求重新检查操作。
