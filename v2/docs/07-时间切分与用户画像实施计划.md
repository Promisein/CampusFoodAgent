## 1. 目标与架构

**目标：** 将 `interactions.jsonl` 转换为可复现的 Train/Validation/Test 数据，并基于目标时刻之前的历史生成可解释用户画像，为后续个性化召回准备可信输入。

**架构：** 原始 processed 文件保持只读。新模块先审计交互和用户稀疏度，再按每个用户的 `(event_time, interaction_id)` 稳定排序执行 leave-two-out 切分；画像构建器分别为验证和测试目标生成快照，画像仓库负责校验、缓存和按用户读取。

**技术栈：** Python 3.11.15、标准库 JSON/JSONL、pytest 9.0.2；不新增训练框架，不使用 GPU。

## 2. 全局约束

- 所有 Python 命令使用 `D:\anaconda3\envs\chedian-eat-agent\python.exe`；
- 所有命令设置 `PYTHONNOUSERSITE=1`；
- 不修改 `v2/backend/data/processed/*`；
- 新产物写入 `v2/backend/data/derived/*`；
- 主评估用户门槛固定为至少 5 条交互；
- 切分固定为最后一条 Test、倒数第二条 Validation、之前全部 Train；
- 画像只能使用目标排序键之前的交互；
- 稀疏和冷启动用户必须保留，不能静默删除；
- 本阶段不修改 `/api/v2/recommend` 的评分行为；
- 不实现 ItemCF、RRF、LightGBM、向量 RAG 或 Agent；
- 每个阶段文档写明年月日；
- 每段只提交本段明确涉及的文件。

## 5. 第一段：交互审计

## 6. 第二段：时间切分

### 6.1 目标

按用户稳定时间顺序生成 Train、Validation、Test 与 Cold/Sparse 保留集，并用 manifest 记录规则与数量。

### 6.2 文件

```text
Create: v2/backend/app/data_pipeline/split_interactions.py
Create: v2/backend/tests/test_time_split.py
Create: v2/docs/09-第二段-时间切分实施记录.md
```

### 6.3 接口

```python
def split_interactions(
    interactions_path: Path,
    output_dir: Path,
    *,
    min_warm_interactions: int = 5,
    source_data_version: str,
) -> dict:
    """写入四个 JSONL 和 split_manifest.json，并返回 manifest。"""
```

每个用户按以下键升序：

```python
(datetime.fromisoformat(row["event_time"]), row["interaction_id"])
```

Warm 用户执行：

```python
train = ordered[:-2]
validation = ordered[-2:-1]
test = ordered[-1:]
```

少于 5 条交互的用户全部进入 `cold_start_interactions.jsonl`，并在每行增加 `user_cohort`，但不改写 processed 源文件。

### 6.4 TDD 步骤

1. 写 5 条交互用户的 3/1/1 失败测试；
2. 实现最小切分；
3. 写 6 条交互用户的 4/1/1 测试；
4. 写少于 5 条全部进入保留集的测试；
5. 写同秒交互按 ID 稳定排序测试；
6. 写输入顺序改变但输出顺序不变测试；
7. 写四个集合没有 ID 重叠且总数守恒测试；
8. 写 manifest 与文件行数一致测试；
9. 运行：

```powershell
& $python -m pytest tests/test_time_split.py -v
& $python -m pytest tests/ -q
```

10. 对真实数据生成 `time_split_v1`；
11. 验证 30,978 / 3,023 / 3,023 / 62,976；
12. 生成 `09-第二段-时间切分实施记录.md` 并提交本段文件。

### 6.5 验收与停止点

- 100,000 条交互均有唯一去向；
- Train、Validation、Test 和 Cold/Sparse 没有重叠；
- 每个 warm 用户的训练排序键小于验证，验证小于测试；
- 输出与输入行顺序无关；
- 本段完成后停止，不生成用户画像。

## 7. 第三段：用户画像快照

### 7.1 目标

为 3,023 个 warm 用户分别生成 Validation 和 Test 两种画像，总计 6,046 条；所有特征只使用目标排序键之前的历史。

### 7.2 文件

```text
Create: v2/backend/app/profiles/__init__.py
Create: v2/backend/app/profiles/build_profiles.py
Create: v2/backend/tests/test_profile_builder.py
Create: v2/docs/10-第三段-用户画像实施记录.md
```

### 7.3 接口

```python
def build_profile_snapshots(
    split_dir: Path,
    businesses_path: Path,
    output_dir: Path,
    *,
    profile_version: str = "profile_v1",
) -> dict:
    """生成画像 JSONL 与 profile manifest，并返回 manifest。"""
```

Validation 画像使用 Train；Test 画像使用 Train + Validation。画像字段：

```text
profile_id
user_id
target_split
as_of_time
cutoff_interaction_id
history_count
history_start_time
history_end_time
category_preferences
price_distribution
mean_price_level
known_price_count
unknown_price_count
mean_rating
positive_rating_ratio
geo_center
geo_radius_p75_km
recent_interaction_ids
recent_business_ids
recent_categories
source_data_version
split_version
profile_version
```

规则：

- 正向评分定义为 `rating >= 4`；
- 类别最多保留 10 个，按次数、平均评分、名称稳定排序；
- 最近交互、商家和类别最多保留 5 个；
- 价格缺失不填充，只计入 `unknown_price_count`；
- 地理中心使用历史商家坐标均值，半径使用到中心距离的 P75；
- `profile_id` 由用户、目标 split、边界和版本确定性生成。

### 7.4 TDD 步骤

1. 写 Validation 画像仅使用 Train 的失败测试；
2. 实现最小画像骨架；
3. 写 Test 画像增加 Validation、排除 Test 的测试；
4. 逐项增加类别、价格、评分、地理和最近行为失败测试；
5. 实现每项最小逻辑；
6. 写缺失价格、稳定排序和稳定 ID 测试；
7. 写 manifest 与 2×warm 用户数量一致测试；
8. 运行：

```powershell
& $python -m pytest tests/test_profile_builder.py -v
& $python -m pytest tests/ -q
```

9. 对真实切分生成 6,046 条画像；
10. 抽查一个用户的 Validation/Test 历史差异；
11. 生成 `10-第三段-用户画像实施记录.md` 并提交本段文件。

### 7.5 验收与停止点

- 每个 warm 用户正好两条画像；
- Validation 画像不包含 Validation/Test；
- Test 画像包含 Validation，但不包含 Test；
- 所有商家字段可追溯到 processed Business；
- 本段完成后停止，不接入推荐 API。
