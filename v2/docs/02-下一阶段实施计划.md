# CampusFoodAgent v2 下一阶段实施计划

> 文档日期：2026年7月15日
>
> 最近阶段目标：把 Tampa processed 数据分段接入 v2 在线 API
>
> 执行方式：每次只完成一段，验收通过并确认后再进入下一段

## 1. 当前起点

当前已经具备：

- Tampa processed 数据及 `data_manifest.json`；
- 3,805 家真实商户；
- 100,000 条 Review 交互；
- 29,092 条代表评论；
- FastAPI v2 后端；
- fixture 硬过滤、规则评分和证据返回；
- 健康、数据状态和推荐三个接口；
- 9 个 API、推荐和数据整理测试。

当前主要断点：

```text
Tampa processed 文件已经生成
            ↓
在线 API 仍读取 5 家 Philadelphia fixture
```

本阶段只解决这个断点。

## 2. 本阶段目标

让 v2 后端逐步完成以下链路：

```text
data_manifest.json
businesses.jsonl
representative_reviews.jsonl
        ↓
真实数据读取层
        ↓
数据状态接口
        ↓
Tampa 推荐接口
        ↓
真实 business ID、距离、评分、理由和评论证据
```

完成后，用户向 `/api/v2/recommend` 提交 Tampa 的位置、半径、价格和查询词，可以获得 processed 数据中的真实商户结果。

## 3. 本阶段非目标

本阶段明确不实现：

- 用户画像；
- 时间切分训练集、验证集和测试集；
- ItemCF 或其他多路召回；
- RRF 融合；
- LightGBM 排序；
- 完整 BM25/向量 RAG；
- LLM 意图解析；
- Agent 工具和多轮状态；
- 收藏、反馈和事件系统；
- 前端；
- 部署和性能压测。

这些能力留到后续阶段，不加入本次四段任务。

## 4. 分段执行规则

1. 严格按第一段到第四段的顺序执行；
2. 一次只开始一段；
3. 本段测试未通过时不进入下一段；
4. 每段完成后汇报修改文件、测试结果和已知边界；
5. 用户确认后再开始下一段；
6. 每段只提交本段涉及的文件；
7. 保留 fixture 文件，便于小数据测试和故障定位；
8. 不修改 processed 数据内容；
9. 所有 Python 命令使用指定 Conda 环境。

环境命令：

```powershell

$python = "D:\anaconda3\envs\chedian-eat-agent\python.exe"
```

```python
class ProcessedDatasetRepository:
    def __init__(self, data_dir: Path): ...
    def load_manifest(self) -> dict: ...
```

### 7.4 请求与过滤规则

- 默认城市从 `Philadelphia` 改为 `Tampa`；
- 仍使用请求中的经纬度计算 Haversine 距离；
- `is_open=false` 的商户不能返回；
- 超出 `radius_km` 的商户不能返回；
- 超出 `max_price_level` 的商户不能返回；
- `price_level` 缺失时，无法证明满足价格上限，因此本段不进入有预算约束的候选；
- 查询词只影响评分，不绕过硬过滤；
- 证据只来自当前候选商户的代表评论；
- 返回结果按分数、距离和 business ID 稳定排序。

### 7.5 评分范围

本段继续使用当前可解释公式：

```text
0.35 × 查询词匹配
+ 0.25 × 平均评分
+ 0.15 × 评论数置信度
+ 0.15 × 距离
+ 0.10 × 价格
```

本段不训练模型，不修改权重，不进行离线调参。

3. 缺少价格字段的处理；
4. 查询词影响排序；
5. EvidenceItem 与当前 business ID 一致；
6. 空候选返回空列表；
7. 排序结果稳定；
8. API 响应不再出现 `v2_yelp_biz_001` 等 fixture ID。
