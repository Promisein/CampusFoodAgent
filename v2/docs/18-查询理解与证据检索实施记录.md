# 查询理解与证据检索实施记录

2026年10月20日，承接16/17阶段，API版本0.3.0、查询链路query_v1。完成查询协议、查询与历史融合、相关评论检索及可复现功能评测。指标与限制见[19实验报告](19-查询与证据评测报告.md)。

## 当前流程

请求 → 中英文规则解析 → 条件取交集 → 需要澄清则空结果并说明 → 城市/is_open/价格/距离/菜系/已见过滤 → 历史三路与查询通道 → RRF → Top K → 商户内相关评论检索。

个性化请求使用已有serving_v1历史画像和三路冻结配置，额外查询通道固定weight=2、budget=100；k沿用60。没有对新场景集做网格选参。无查询命中时保持过滤后的历史推荐并返回query_no_lexical_match；查询通道异常时返回query_unavailable并保留健康通道。未知用户可使用查询与地理热门，画像整体缺失时退回受相同查询条件限制的规则路径。

匿名请求保留processed_geo_keyword_evidence引擎名称和请求协议，行为升级为查询条件过滤及规则/查询RRF；不能再认为匿名排序分值与旧版完全相同。个性化有查询候选时engine为personalized_query_rrf；需要澄清时为query_needs_clarification。没有增加外部服务、API Key或模型下载。

## 解析协议与限制

`metadata.intent`返回include_categories、exclude_categories、soft_topics、radius_km、max_price_level、unresolved_constraints、needs_clarification、lexical_terms及版本。

| 项目 | 行为 |
|---|---|
| 菜系/类别 | 咖啡、披萨、中餐、日料、寿司、墨西哥菜、泰餐、意大利菜、汉堡、海鲜、早餐、纯素、素食的预定义中英文别名 |
| 多类别 | include取并集，exclude全部排除；同类同时包含/排除则澄清。类别是Yelp标签，不是饮食安全认证 |
| 排除 | 支持“不要披萨和汉堡”“no pizza or burgers”等简单协调否定；复杂语法没有通用语言模型保证 |
| 距离 | `2公里内`、`within 2 km`等最大半径，和请求radius_km取较小值；不支持最小距离等其他算子 |
| 价格 | `价格等级不超过2`、`price level 2`，和max_price_level取较小值。它是1–4等级，不是金额 |
| 软偏好 | 安静/聊天/约会/户外及有限英文词；只用于词汇相关性，不作为严格事实过滤 |
| 无法可靠满足 | 金额预算、过敏保证、部分饮食认证、现在营业、已检测到的未知明确排除/冲突：返回空结果与澄清原因 |

协议是有限规则语法，不能声称理解任意中文或英语。类别条件只查结构化类别；未知词可能只能作为英文关键词，未识别的复杂自然语言仍需扩展评测。`is_open`依然只是数据集状态，当前营业请求不会被它冒充满足。

显式请求字段不会被文本放宽。菜系过滤在每路Top100之前执行，最后再次通过白名单核验；空交集直接空列表，不移除约束凑推荐。模型整体不可用时无法恢复历史seen，响应明确model_unavailable；单通道故障仍保留已知seen。

## 查询与评论检索

`retrieval/query.py`实现名称/类别词汇匹配及候选集合内IDF加权；软偏好增加相关评论提及信号。这不是BM25、向量语义或学习排序模型。每个请求临时计算，只覆盖当前合法候选。历史热门、ItemCF、类别TF-IDF算法及旧冻结参数不重新训练。

`evidence.py`在返回商户的代表评论中按匹配词数选择相关句子，最多返回2条，保留原全文、原始document_id、business_id、excerpt、matched_terms和relevance_score。外国商户的评论不引用，重复ID去重，excerpt必须来自原文。

evidence_status为related_mentions、insufficient或not_requested。“not quiet”也可能是相关评论，因此related_mentions不等于支持“安静”；响应和理由明确提示核对上下文。没有匹配就标证据不足，不用无关评论填充。评论仅作数据，不执行其中指令，也不通过LLM生成额外事实。

## 使用与复现

在v2/backend、既有chedian-eat-agent环境运行：

```powershell
python -B -m pytest -q
python -B -m pip check
python -B -m app.evaluation.query_study
python -B -m uvicorn app.main:app --port 8100
```

评测默认只使用提交的8家合成商户及22个人工场景，无需原始Yelp文件或本地serving模型；在临时目录导出小型画像，正式数据不修改。输出data/derived/query_v1，含metrics.json、cases_results.json、experiment_manifest.json。完整目录发布与SHA256校验沿用既有工具。

真实推荐需要processed商户/评论；传user_id时可复用16阶段serving_v1。没有有效模型时按协议降级；没有基础商户时503。启动后POST `/api/v2/recommend`示例：

```json
{
  "query": "披萨，价格等级不超过2，3公里内，适合聊天",
  "user_id": "a-local-yelp-user-id",
  "latitude": 27.9506,
  "longitude": -82.4572,
  "radius_km": 10,
  "max_price_level": 4,
  "top_k": 5
}
```

响应resolved_constraints应为半径3、价格等级2；菜系为pizza，聊天对应相关评论提及。不要把示例中的任意ID当作已注册账户。
