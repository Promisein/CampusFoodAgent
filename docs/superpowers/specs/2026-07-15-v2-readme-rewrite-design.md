## 目标

将 `v2/README.md` 重写为中文项目入口，并把《推荐系统与餐饮 Agent 双项目重构方案》及“项目重构方案”目录中七份关联文档的核心内容直接整合进 README。README 既要帮助读者运行当前版本，也要清楚说明目标架构、实验计划、双项目分工和可信度边界。

## 读者与用途

- 开发者：能够根据 README 安装依赖、启动 API、调用接口、整理 Yelp 数据并运行测试。
- 面试官：能够快速理解项目定位、当前完成度、目标架构、关键取舍和可验证证据。
- 项目维护者：能够分辨已实现能力、正在建设能力和长期规划，避免把计划写成成果。

## 内容结构

README 按“先可运行、后讲方案”的顺序组织：

1. 项目名称、文档日期和一句话定位；
2. 当前版本状态与可信度说明；
3. 已实现能力、目录结构和技术栈；
4. 环境准备、启动、接口调用、数据整理和测试命令；
5. 当前推荐流程与 API 契约；
6. 数据来源、数据取舍、许可与本地文件边界；
7. 目标架构、模块职责和推荐/RAG/Agent 分工；
8. 推荐层、RAG 层和 Agent 层的评估计划；
9. 分阶段路线图、风险止损和完成定义；
10. 与 `recsys_pipeline` 的职责边界、可信度原则和面试表述；
11. 方案来源与原始文档路径。

## 状态表达规则

- “已实现”只描述当前 `v2` 代码和测试能够证明的能力：FastAPI v2 接口、fixture 推荐、城市/距离/价格/营业状态硬过滤、关键词与结构化评分、代表评论证据、Yelp 单城市数据整理和 manifest、现有自动化测试。
- “规划中”描述用户画像快照、地理热门/ItemCF/语义/冷启动多路召回、RRF、LightGBM、完整混合 RAG、受控 Agent 工具、事件反馈和故障降级。
- 未产生的实验指标使用“待运行后记录”，不填写估算数字，不声称线上 CTR、A/B 测试或实时个性化。
- LLM 只承担意图理解、工具编排和证据解释；硬约束、候选生成和事实字段由代码与数据控制。
