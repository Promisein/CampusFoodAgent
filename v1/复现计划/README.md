# 复现计划总览

## 目标

从零开始复现"成电吃什么 Agent"后端与前端，每章聚焦一个模块，章末有可运行的成果。

## 章程

| 章节 | 内容 | 预计时间 | 产出 |
|---|---|---|---|
| 第 1 章 | 项目脚手架 | 1 小时 | FastAPI 跑起来，能访问 /docs |
| 第 2 章 | 数据层 | 2 小时 | SQLite 建表 + CSV 种子数据 + 店铺查询 |
| 第 3 章 | 规则引擎 | 3 小时 | 输入大白话，输出排序后的推荐列表 |
| 第 4 章 | API 路由 v1 | 2 小时 | 完整的 /api/v1 端点集合 |
| 第 5 章 | AI 引擎 | 3 小时 | 接入 DeepSeek V4，实现混合推荐 |
| 第 6 章 | 用户认证 | 2 小时 | JWT + 微信登录 + 匿名身份 |
| 第 7 章 | 配套功能 | 3 小时 | 反馈、收藏、广告、排行、用户画像 |
| 第 8 章 | Next.js 前端 | 4 小时 | Web 端完整交互 |
| 第 9 章 | 微信小程序 | 4 小时 | 小程序端完整交互 |
| 第 10 章 | 测试与部署 | 2 小时 | 测试覆盖 + 部署上线 |

## 使用方式

每章一个 md 文件，按顺序阅读和实现。每章的文档结构：

1. **本章目标** — 要做出什么
2. **前置知识** — 需要提前了解的概念
3. **文件清单** — 本章要创建/修改哪些文件
4. **逐步实现** — 每一步干什么、为什么这么干
5. **验证方法** — 怎么确认做对了
6. **常见坑** — 容易出错的地方

## 核心原则

- 每章结束必须有**可运行的产物**，不是写了一堆代码跑不起来
- 先跑通再优化，不要一开始就追求完美
- 理解"为什么"比写出代码更重要
